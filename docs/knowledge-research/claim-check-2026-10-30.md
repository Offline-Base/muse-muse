Also found:

- Our stage 4 Spark plan in /Users/ethancastro/muse-muse/docs/KNOWLEDGE_UPDATE.md ('QLoRA needs about eight H100s', '$150 to $250 an attempt on 8 GPUs') has no support in Meta's docs. BF16 weights (1.64 TB) exceed 8x H100 (640 GB) and 8x B200 (about 1.44 TB). The smallest documented open-source LoRA setups are 16 GB300 (TorchTitan), 16 GB200 (Megatron Bridge image-text LoRA), 32 GB200 (NeMo AutoModel) and 64 H100 (TRL). Only Fireworks serverless LoRA trains on the NVFP4 base.
- A Glimmer fine-tuned on Q&A written by Spark Open is a 'Derivative' under the Muse Model License ('trained ... using ... any outputs or results thereof'). Publishing it means shipping the Muse Model License, the Usage Policy and the copyright notice with the weights, displaying 'Built with Muse Spark Open', and following the Usage Policy. So the tuned model is not plain Apache 2.0 in practice. The Usage Policy also bars presenting outputs as human-generated, so the dataset should be labeled as Spark Open-generated.
- Spark Open's model card lists 'Synthetic Data Generation - generating high-quality training data for downstream model development' as an intended use, which supports our plan to have Spark Open write the training data.
- Glimmer's chat template writes 'Knowledge cutoff' and 'Current date' only when there is no system message. Any training or eval example with its own system prompt shows the model no cutoff line. Spark Open's template always prepends that block. Glimmer's template takes a knowledge_cutoff kwarg, so the tuned cutoff can be set without editing the template.
- On Fireworks, a trained Spark Open LoRA is served only on a dedicated deployment, not per-token serverless. The account may also need Fireworks to enable Spark Open training. Both affect cost.
- TorchTitan's Spark LoRA recipe notes that Hugging Face exports omit the adapters (only native checkpoints keep them), so taking an adapter out of TorchTitan needs its own conversion step.
- Pin Glimmer to revision a4e59da52a7bc87ae7251dd5545c0dd437c44b68, which Meta's cookbook uses. Later commits up to the current main cec94fcf changed only the README and eval files. The official GGUFs were re-uploaded on 2026-08-12 with a fixed chat template, so older downloads have a broken template.
- Meta's dev.meta.ai post-training pages link to github.com/meta-models/meta-oss-cookbook/tree/main/post-training/..., which has returned 404 since the 2026-10-15 restructure. The real paths are muse-glimmer/post-training/... and muse-spark/post-training/...
- The handoff's community Glimmer quant sizes (Q1_0 4.52, IQ1_S 6.08, IQ1_M 6.58 'GB') are GiB. The decimal file sizes on huggingface.co/NANI-Nithin/Muse-Glimmer-30B-GGUF are 4.85, 6.53 and 7.06 GB. Unsloth's smallest Glimmer GGUF is UD-IQ2_XXS at 10.75 GB, and Unsloth's guide claims Glimmer fine-tuning on a 24 GB card, while Meta's cookbook still lists Unsloth SFT as 'Planned'.
- Meta's Glimmer docs list no hardware below 24 GB VRAM (or 48 GB Apple unified memory) and say nothing about Jetson or 8 GB devices. The Jetson target has no official support.
- dev.meta.ai/license shows the Llama 2 Community License, which has a 700M MAU cap and a ban on using outputs to improve other LLMs. Neither clause is in the Muse Model License, and this page is a likely source of mix-ups in AI-written reports.
- Both Spark Open Hugging Face repos are gated with 'manual' approval, so access may not be instant. Meta also offers a direct download after sign-in. Unsloth's GGUF repo is ungated and carries the identical license.
- The Glimmer repos ship a USAGE_POLICY.md (18+, prohibited uses) next to the Apache 2.0 LICENSE. Apache 2.0 does not incorporate it, so how far it binds users is unclear.
- Version floors: Glimmer needs transformers 5.15 or later. Spark Open needs 5.19 or later per Meta's docs, but Megatron Bridge's README says native HF execution needs 5.20 or later.
- Meta's help page on output copyright cites 'Section 5.1' for output ownership, but in the Oct 9, 2026 terms that clause is section 4.1. The help center has not caught up with the terms.
- Megatron Bridge publishes Spark Open text pretraining recipes (192 or 256 GB200) and the Spark TRL section mentions continued pre-training, but no Meta source documents continued pretraining on raw text for Glimmer.

Also found:

- The NANI card labels GiB as GB. The real files are 4.85 GB (Q1_0), 6.53 GB (IQ1_S) and 7.06 GB (IQ1_M). Use bytes or GiB consistently in the plan and the handoff.
- Mainline's Q1_0 quantizer ignores the imatrix and stores only sign times mean absolute value per 128 weights, which is RTN binarization. Q1_0 was built for natively 1-bit Bonsai models. The Glimmer Q1_0 file is almost certainly unusable, and a better imatrix cannot fix that.
- Glimmer's text model is about 27.86B parameters (GGUF size_label 28B). The real average bpw of the NANI files is 1.39 (Q1_0), 1.87 (IQ1_S), 2.03 (IQ1_M), 2.29 (IQ2_XXS) and 2.83 (IQ2_M).
- For low-bit tests use b11970 or newer, not b11574. b11970 includes PR #30517, which sped up q1_0, iq1_s and iq1_m decode by about 20% on a small Ampere GPU. b10353, the Glimmer minimum, has no Linux CUDA arm64 build at all.
- IQ1_M has no CUDA MMQ kernel in mainline. Prompt processing falls back to dequantizing and cuBLAS, which is slower and needs temporary buffers. On an 8 GB board that adds memory risk. IQ1_S and Q1_0 do have MMQ.
- A failed GPU allocation has frozen and rebooted our boards. Run any Glimmer Jetson test on a board in maintenance (jetson-03 or jetson-04 style), never on jetson-05, which hosts the control plane.
- Glimmer's chat template inserts a system block and defaults to 'Reasoning strength: high'. At 512 context and an estimated 6 to 10 tok/s, set reasoning to low. Tool definitions alone may overflow 512 tokens.
- Quantization can wipe out small fine-tuning deltas: 4-bit quantization raised retained 'unlearned' knowledge from 21% to 83% (arXiv 2410.16454). Any quantized Glimmer or student must be re-scored on the new 2026 facts. An imatrix computed on 2026 text is worth testing.
- With a 202,048-token vocabulary, the output tensor alone is about 1.35B parameters, about 1.1 GB at Q6_K in the Q1_0 file. That is why real bpw sits well above nominal. Keep token_embd on the CPU via mmap, as the fleet does for Bolt.
- Granite 4.2 3B (Apache 2.0, released Aug 25, 2026) is the newest permissive 3B base and may need fewer post-cutoff facts taught. Bolt E4B (OpenMDW-1.1) is the only permissive 4B-class student already measured on our JetPack 7 boards.

Also found:

- Our earlier government.md note on BIS ('Non-commercial, 400-word extracts, training-only at most') is wrong for BIS statistics. Data Portal statistics, including policy rates and FX, can be used and republished commercially if we cite the BIS and add no extra charge for them.
