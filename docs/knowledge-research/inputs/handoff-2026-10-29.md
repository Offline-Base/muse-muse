## 1. Objective and hard boundaries

We want to close the knowledge gap from **January 4 through October 29, 2026** for **both** Meta models, then refresh factual knowledge **weekly** afterward.

1. **Muse Glimmer 30B**: Update knowledge, preserve general reasoning/tool-use abilities, download/merge final weights if adapters are used, **quantize only this model** as far as feasible for **Jetson Orin Nano 8 GB**. Goal is a useful offline text-only system if feasible. Vision support is optional and likely out of reach on this hardware.
2. **Muse Spark Open 816B total / 42B active MoE**: Update its knowledge for cloud use. **Do not newly quantize Spark** as part of the project. Existing supplied NVFP4 checkpoints are acceptable if needed for serving/adapter training, but the target deliverable is a high-quality cloud model plus adapter/checkpoint.
3. Learn verifiable facts, not merely memorize benchmarks or misrepresent a changed cutoff date. Distinguish narrow SFT, LoRA-based continued LM adaptation, and true full-parameter continued pretraining.
4. Use one shared, provenance-rich corpus, plus separate training/evaluation variants. Preserve separate model-specific splits and adapters.
5. Stay within budget and actual credit eligibility. Never launch costly GPU infrastructure without an explicit cost and feasibility gate.

### Brief B: *An exhaustive, legally clean training dataset for January 4 to October 29, 2026*

This is the **source, license, and training-method specification**. It covers open data around the world, Wikidata and Wikipedia snapshots, Common Crawl, CC-NEWS, GDELT, government/public data, scholarly datasets, software releases, social/forecasting sources, expiring feeds, licensing restrictions, model-output terms, and legal questions. It asks for ready-made 2026 corpora, independent verification of risky source/license claims, writer-model choice and synthetic data terms, continual knowledge-learning techniques, evaluation benchmarks, and cloud credits.

Its proposed dataset tree:

```
facts/       # atomic facts; source IDs; temporal validity; provenance
 documents/  # source text; license-aware visibility/training permissions
 synthetic/  # document-grounded rewrites and questions
 sft/        # chat training pairs, abstention and time-aware responses
 eval/       # held-out facts, cutoff ladder, forgetting/regression sets
 replay/     # base-model general prompts to maintain broad abilities
```

Normalize that tree into implementation specs rather than treating these as already-existing files.

The briefs explicitly require cautious validation: primary-source URL + checked date; every historical event date verified independently; a licensing verdict per source; no invented model versions; mark unverified claims. Claims about Meta's API Terms section 10.1(ix), Exa terms, CC-BY-SA derivatives, robots training opt-outs, and other licensing restrictions are **research hypotheses until current primary legal text is checked**. A private copyrighted dataset does not automatically make training legally permissible. Have counsel assess uncertain cases.

## 5. Proposed modeling and training experiments

**Do not treat the following as a proved best recipe.** Run a measured study before scaling.

1. **Build data and held-out evaluations first.** Record event dates, publication times, knowledge validity intervals, references, license status, source language, Wikidata IDs, confidence and data version. Maintain as-of queries. Avoid source/date leakage into tests.
2. **Baseline both unmodified models** on 2026 facts, false premises, unknown/unresolved events, old-world knowledge, reasoning/tool use, and multiple languages. No internet/tool access during closed-book factual tests. For separate RAG tests allow retrieval and label those results clearly.
3. **Glimmer pilot via Fireworks free SFT** on a small licensed, verified 2026 Q&A set. Download adapter to prove export is real, match base revision, run a merge on Lambda, and evaluate. Free SFT is time-limited, so prioritize validating it before November 30.
4. **Continued-pretraining comparison on Lambda**, not one untested fixed recipe. Test at least (a) plain factual SFT, (b) LoRA-based language-model continued adaptation on raw documents, (c) document-grounded knowledge-seeding/on-policy distillation if paper/code support it. Compare SFT->CPT->short SFT refresh against CPT->SFT. SFT before CPT can be weakened by the subsequent raw-text objective. Fireworks may not permit uploading a custom modified base for its free managed SFT, so keep alternate adapters/checkpoints and do the final instruction refresh on Lambda if needed.
5. **Spark pilot**: check checkpoint type, training recipe, exact GPU memory, export, optimizer and activation RAM, multi-node availability, minimum duration, and $250/day cap. Only then commit a short smoke test on Lambda. If hardware insufficient, document that fact and propose a hosted LoRA alternative with separate cash cost. 816B full-parameter continued pretraining is **not demonstrated to be affordable** with current credits.
6. **Quantize Glimmer only after quality is established**: keep original/adapter/merged BF16 and a reference Q4. Try IQ2, IQ1_S, Q1_0 and any research sub-bit methods in a reproducible matrix. Distinguish mathematical bit-per-weight bounds from real GGUF weight bytes and runtime RAM. Prioritize measured retained accuracy over file size.
7. **Jetson experiment**: use a recent llama.cpp build with Jetson CUDA support and text-only weights; headless; low context; log RAM/VRAM/CUDA allocations, tokens/sec, perplexity, hallucination, old/new fact recall, energy. Have a 3B–4B distillation fallback.
8. **Weekly refresh**: ingest sources with stable identifiers, dedupe, validate, add new time-aware facts; rerun regression and rollback if needed. Prefer local retrieval for rapidly changing facts; evaluate weight-only knowledge independently.

Important research candidates mentioned in Brief B, **not yet validated as production-ready for this model**: `Language Models Need Sleep: Learning to Self-Modify and Consolidate Memories` (arXiv:2606.03979), Hope/Nested Learning (2512.24695), SEAL (2506.10943), Cartridges (2506.06266), TRL GKD trainer, knowledge seeding, replay, adapter stacking, and distillation. Claude should compare published setups, architecture requirements, memory, compute, actual code, and independent replications. No assumed transfer from paper benchmarks to Glimmer/Spark.

## 6. Measurements and go/no-go gates

- **Coverage**: document and atomic fact counts by date, region, language, topic, story size; audit using Wikidata/public records/news event clusters without violating data-source terms.
- **Closed-book 2026 accuracy** on source-disjoint, held-out questions; compare with pre-cutoff model baseline. Include ambiguous/open stories and deliberate false-premise questions.
- **Retention**: 2025-and-earlier recall, reasoning, structured output, tool use; measure statistically significant changes with confidence intervals.
- **Contamination**: enforce source/event/answer split, paraphrase-near-duplicate detection, dated holdouts, no Gemini-report prose copied into test labels unless independently sourced.
- **Training costs**: measured tokens/sec, optimizer steps, GPU-hours, storage/egress, API inference, evaluation, preprocessing, failed trials, and resulting cost per newly learned reliable fact.
- **Quantization**: model quality vs Q4 baseline and merged BF16; load success on the real Jetson; max memory over long generations; sustained tokens/sec.
- **Artifacts**: dataset manifests, immutable source snapshots, model and adapter revision IDs, training config, package lockfiles, seed, logs, evaluation JSONL, quantization command line, hardware profiles.
