# Contracts

Every module codes against this file. Shared dataclasses are in `base/types.py`, settings in `base/config.py`. If you need a contract change, make it here and in the code together, and say so in your report. This file describes the code as of Oct 27, after integration and the review fixes (see the last section).

## Data flow

```
Muse (cloud VM) --MCP over HTTPS--> relay (Cloudflare Worker) <--WebSocket dialed out by device-- base/connector/relay_client.py
                                                                                       |
                                                                         base/connector/server.py (127.0.0.1:8790)
                                                                                       |
     tool call -> restore tags in arguments -> workspace / jobs -> raw local result (real names, stays here)
                                                                                       |
            guard.tag(raw, llm_names=Glimmer's second pass) -> TagResult
            + request topics (never-share keywords in Muse's request, Glimmer's request_topics pass) -> router.decide() -> RouteDecision
                                                                                       |
               share_tagged: tagged text | share_summary: local summary, tagged | ask_user: approval row, wait | refuse: held message
                                                                                       |
                                         egress.final_check(text) (leak check, last line of defense) -> Muse
```

`base/egress.py` is the single exit. Every connector tool result goes through `egress.release(...)` or `egress.resolve(...)`, which run the router outcome and a final leak check against the roster, the persistent tag map and `guard.find_identifiers`. If the final check finds anything, the result is replaced with "Held on your device." and an audit row records `egress_blocked`. No other code path returns document-derived text to Muse.

`Settings.paths` gives `db` (home/base.db: decisions, jobs, audit, heavy and dreaming tables), `output` (home/output), `adapters`, `tagmap` (home/tagmap.json), `router_prompt` (home/router_rules.md), `connector_token` (home/connector_token), `scans` (home/scans) and `regions` (home/regions). `ensure_home()` makes home, output and adapters with mode 0700. Not in Settings, read only by scripts: HEAVY_TOKEN (base/heavy/worker.py), LLAMA_SERVER_BIN, GLIMMER_GGUF, ANSWER_CTX, ROUTER_CTX (scripts/start.sh), SAM_MODEL_DIR, SAM_MODEL_ID (scripts/start_sam.sh). All are in `.env.example`.

`assert_synthetic(settings, folder)` raises `CloudBackendRefused` when the backend is a cloud endpoint and neither the folder nor a parent of it up to and including `settings.workspace_root` has a `.synthetic` file (`synthetic_marked(folder, root)`). A marker above the workspace root never counts, and a folder outside the root is refused. The index, the agent and egress call it before any document text can reach a cloud model.

`DEVICE_ONLY=1` (Settings.device_only): every model is on this device, and `guard.Redaction.name_shapes` tags capitalized words shaped like a name as `[Person N]` with no model, unless a folder sends real names or a never-redact word covers them. `PRIMARY_MODEL` defaults to lfm, and LFM3-VL-2B on the checker's llama-server answers every step, the router included, whatever `GLIMMER_BACKEND` says. `PRIMARY_MODEL=glimmer` is allowed only with `GLIMMER_BACKEND=llama_server` on loopback addresses. The Jetson gateway settings and the Meta API key are dropped, so no remote client can be built. When the model is down there is no fallback: the checks fail and results are held.

## Types (`base/types.py`)

- `Person(name, first, last, nicknames=(), role="student", student_id=None)`; `Roster(teacher, students: tuple[Person, ...], school=None)`; `Roster.people()` yields teacher then students. Frozen; `load_roster` returns tuples.
- `Hit(kind, value, start, end)`, kind one of `student, teacher, person, phone, email, ssn, card, otp, student_id, address, dob` (`IDENTIFIER_KINDS` is the last eight). Egress may also report `check_failed`.
- `TagResult(text, tag_map, hits, blocked, topics)`: `tag_map` maps each tag used in this text (like `[Student C]`) to its real value; `blocked` holds plain reasons, `topics` the never-share topic names.
- `Decision` is `share_tagged | share_summary | ask_user | refuse`; `STRICTNESS`, `stricter(a, b)`, `default_share_form(kind, topics=())` (`share_summary` for `class_aggregate` or when `CLASS_LEVEL_TOPIC` (`"class_level"`, a request topic) is in `topics`, else `share_tagged`).
- `RouteInput(request, result_kind, tagged_text, hits=[], blocked=[], summary=None, topics=[], request_blocked=[])`: `hits` are the result's plus the identifier hits in Muse's request; `request_blocked` lists the never-share topics named only in Muse's request, not in the result (they stay in `topics` too). `RouteDecision(decision, reason, source, latency_ms=0, floors=[])`, source `model | rule | fallback | cache`.
- Result kinds: `document_list, snippet, per_student, class_aggregate, contact_info, sensitive_record, free_text, dreaming_report`.

## Guard (`base/guard.py`)

- `load_roster(path) -> Roster`. `GuardError` for an unreadable tag map or text that still has private values after tagging.
- `find_identifiers(text, roster=None, *, allow_test_ssn=True) -> list[Hit]`: Luhn-valid 13 to 19 digit cards, SSNs (000 and 9xx areas accepted unless `allow_test_ssn=False`), US phone formats, emails, one-time codes next to code/OTP/PIN/verification, student ids (`S` or `ID` plus 5 to 8 digits, and the roster's id shape when a roster is given), numbered street addresses, dates of birth next to born/DOB/birthday. Plain calendar dates are not identifiers.
- `find_names(text, roster)`: full names, first names, capitalized last names, nicknames, possessives, a teacher's title plus last name, one-edit misspellings of capitalized 4+ letter tokens that are not common words. A first name two students share becomes `[Person N]`; relatives with a roster surname too (up to two capitalized words before it, accented ones included: Émile Tindall).
- `TagMap(path=None, *, seed=None)`, `TagMap.load(path)`, `TagMap.for_settings(settings)`: persistent at `settings.paths.tagmap`, written 0600 atomically. Students get `[Student A]`... in a per-device shuffled order, the teacher `[Teacher]`, others `[Phone 1]`, `[Email 1]`, `[SSN 1]`, `[Card 1]`, `[Code 1]`, `[ID 1]`, `[Address 1]`, `[DOB 1]`, `[Person 1]`. Same value, same tag. Methods: `tag_for(kind, key, value)`, `ensure_roster(roster)`, `get(tag)`, `kind_of(tag)`, `as_dict() -> {tag: real value}` (a student's value is the full name), `values()`, `save()`, `flush()`.
- Every scan (tag, leaks, find_names, find_identifiers, blocked_topics) runs on a normalized copy of the text and maps spans back: NFKC, format characters removed (soft hyphen, zero-width spaces), every dash as `-`, modifier apostrophes as `’`, `_` as a space, and line-break hyphenation joined. Name and keyword matches need a non-letter on each side, so `camila_iep_goals.md` shows a name and the `iep` topic. A name in single quotes counts (‘Maya’, 'Maya'); only an apostrophe right after a letter blocks one (the Callaghan in O'Callaghan). A lowercase last name of 4+ letters that is not a common word counts. Identifiers also cover en dashes and non-breaking hyphens, dotted card numbers, `S-401127`, a 9-digit run within 30 characters of ssn/itin/social, and lowercase street addresses with a plain street word. `long_digit_runs(text)` lists runs of 7+ digits (alone or joined by `-` or `.`) that are not dates. `name_occurs(name, text)` is the flexible check the model's name pass uses, and `occurring_names(name, text)` gives the name if it occurs, else each of its words that does.
- `tag(text, roster, tagmap, llm_names=None, never_share=None) -> TagResult`: identifiers, roster names, every real value already in the tag map, then names from `llm_names(text)` (the local model's second pass) as `[Person N]`, lowercase ones included. Longest span first, never inside a tag, re-scanned until clean. If `llm_names` raises, so does `tag`. How model-found names are tagged:
  - A trailing possessive or punctuation is dropped from each name ("Bennick's" and "Cinderfall." count as the bare name).
  - Each word of a model name is also tagged alone, with its own `[Person N]` (a later "Bennick" when the model reported only "Bennick Cinderfall"), and so is each 3+ letter piece of a hyphenated word. Titles, the suffixes jr, sr, ii, iii and iv, and particles (de, la, van) that are lowercase or not the first word are left out. Any other lowercase word counts ("Bennick cinderfall").
  - A name or word that is also a common word (Mason, Grace, May) is tagged only where the text capitalizes it and does not use it as the word, with the roster's rules: not before a subject pronoun ("Will you"), not after a determiner, and a month not next to a number or after "in" ("May 5"). A known value that is a common word follows the same rules in later texts. A common word under 3 letters, a pronoun, a determiner or a title is never tagged from the model pass, and a name whose words are all roster forms, or a word that is one, is left to the roster pass.
  - A one-word name the model reported on its own, not as a word of a longer name it also reported, takes in up to two capitalized words on each side, only where the text capitalizes the name and only across spaces or tabs (not a comma or a line break): "Cinderfall" alone still tags "Bennick Cinderfall". Each word it takes in is tagged alone where the text capitalizes it. This is one step: a word taken in takes in nothing more. A word is not taken in when it is a common word, a title, a roster name, one letter, touches a digit or an identifier (the "S" of S401399), is in capitals next to a name that is not (IEP), is written in lowercase elsewhere in the text, or is a greeting, label or role word (Hi, Overall, Nurse, Contact; `guard._NOT_NAMES`). A possessive ends the name before its 's ("Ona Thistlewood's group" tags "Ona Thistlewood"). A name the model reported with two or more words takes in nothing.
  - Every value the model pass gave (the reported names, their words, a fuller name and the words it took in) is stored in the tag map as a known value, also where a longer span covered it in this text. A common word is stored only where it was tagged alone. So a later text with only "Bennick" or "Cinderfall" is tagged with no model call, and `leaks` (egress final_check) reports it.
- `restore(text, tag_map)`: tags back to values, tolerant of `Student A`, `student a`, `Student A's`, `(Student A)`; accepts a dict or a TagMap.
- `blocked_topics(text, never_share)`, `blocked_reasons(text, never_share)` (wording in `TOPIC_REASONS`, else "Mentions <topic>"), `leaks(text, roster, tagmap) -> list[Hit]` (used by egress and the eval): everything tag() would find plus full names of 8+ letters spelled run together, letter by letter, slugged or reversed, so final_check is stricter than tag().

## Model clients

`base/local_llm.py`:
- `LocalLLM(settings, role="answer"|"router", *, client=None)`. The httpx client has `trust_env=False`: no environment or system proxy. `chat(messages, *, max_tokens=2000, json_schema=None, tools=None, tool_choice=None, reasoning="low", adapter=None, timeout=None, synthetic=False)` (timeout None: 120 s, or on llama_server `max(120, max_tokens / 5 + 60)` s; connect 10 s; a read timeout on llama_server is not retried) -> ChatResult(content, tool_calls, reasoning_tokens, prompt_tokens, completion_tokens, latency_ms, model, finish_reason, provider)`.
- On a cloud backend every call must pass `synthetic=True` or it raises `CloudBackendRefused`. openrouter sends `reasoning: {"effort": ...}`; llama_server sends `chat_template_kwargs.reasoning_strength` and, with `adapter`, `lora: [{"id": int, "scale": 1.0}]` (an adapter on openrouter is a `ValueError`). A `Reasoning strength:` line is added to the system prompt if missing. A reply cut off with no content is retried once with double the budget, then `LLMTruncated`.
- `chat_json(messages, schema, **kw) -> dict` (schema plain or `{name, strict, schema}`), one retry, then `LLMParseError`. Both subclass `LLMError`.
- `llm_names(text, *, synthetic=False, max_tokens=1500) -> list[str]`: names Glimmer finds, kept only where they occur in the text (`guard.occurring_names`: apostrophe, space and case differences allowed). A name that does not occur whole keeps each of its words that does, so "Bennick Cinderfall" over "Cinderfall, Bennick", or a misspelled last name, still tags the words that are there. `health()`, `close()`.
- `request_topics(request, topics: Mapping[str, str], *, synthetic=False, max_tokens=1500) -> list[str]`: the policy's request topics (name -> description) that Muse's tagged request matches, one strict-JSON call whose schema enumerates the names; returned in policy order. No call for an empty request or no topics. Measured against hand labels in eval/reports/request_topics.md (`scripts/check_request_topics.py`).

- `FallbackLLM(primary, fallback)` (PRIMARY_MODEL=lfm, which needs CHECKER_BACKEND=lfm and sets it by default): the same `chat`, `chat_json`, `llm_names` and `request_topics`, sent to LFM3-VL-2B (the checker client) first and, on any `LLMError`, again to Glimmer with the same arguments, so Glimmer's cloud refusal still applies. The adapter goes to Glimmer only; a call with tools goes to Glimmer only. `last_used` is the model that answered this thread's last call (the agent's `model_log` records it). Services wires it for `answer_llm` and `checker_llm` with the fallback `LocalLLM(settings, role="jetson")` when `JETSON_LFM_BASE` (https only) and `JETSON_LFM_API_KEY` are set, else Glimmer's answer client; the router stays on Glimmer, and scans and passage picking stay on LFM with no fallback. The `jetson` role (backend `gateway`, model `JETSON_LFM_MODEL`, default `hf.co/LiquidAI/LFM3-1.7B-GGUF:Q4_K_M`) sends the checker's Liquid request to the user's Jetson through the Offline Base gateway; it is remote, so `is_cloud` is True and every call must pass `synthetic=True`. `health()` there is GET `/models`.

`base/spark.py` (eval and synthetic data only):
- `Spark(settings, roster=None)`: `chat(messages, *, max_tokens=4000, json_schema=None, effort="minimal", cache=True) -> SparkResult(content, usage, cached, finish_reason)`, `chat_json(messages, schema, **kw)`. Cache and usage in `eval/.cache/spark.db`, table `spark_calls(ts, model, prompt_tokens, completion_tokens, reasoning_tokens, cached, cached_tokens)`; `usage_summary(cache_path, since=None)`.
- Raises `SparkRefused` (a `SparkError`) for any roster name, nickname or identifier, and for every call if base.guard cannot be imported.

## Workspace (`base/workspace/`)

- `index.py`: `DocumentIndex(settings)`: `list(folder) -> list[Doc(id, path, title, size, modified)]` (recursive; `id` and `path` are the POSIX path relative to the workspace root, never absolute; `title` is the first markdown heading or the file stem), `read(doc_id) -> str`, `search(query, k=5, folder=None) -> list[Snippet(doc_id, title, text, score)]` (BM25 over .md/.txt, no embeddings), `resolve(name)`. Titles are found with a linear pattern on the first 2000 characters. list and search also check the marker on each file's resolved folder. `passages(queries, k=20, folder=None) -> list[Snippet]`: every readable document cut into ~800-character pieces (150 overlap), each piece ranked by BM25 and, with an embedder, by meaning, for every query; reciprocal rank fusion over all those rankings, at most 3 pieces per document, `Snippet.text` the whole piece. `Rag.queries(question)` is the question plus up to 3 queries the checker writes (tags restored, the question alone if the call fails); `Rag.retrieve(index, question)` is `index.passages(queries)`. search_documents uses retrieve then `Rag.pick`, and sends up to 600 characters of each picked passage, centered on the query words; without the checker it keeps `search` and 300-character snippets. A PDF's or image's title is its file name with `_` as spaces. Hidden files, files over 5 MB and links out of the root are skipped. `.pdf` files are documents when `pdftotext` is installed (`PDFTOTEXT_BIN`, else PATH): their text layer, read on the device and cached until the file changes; a PDF that will not read is skipped in search. With `SEARCH_EMBEDDINGS=1` the index gets an `Embedder` (`base/workspace/embed.py`, EmbeddingGemma 2 on this device's llama-server, `EMBED_URL` loopback only, `scripts/start_embedder.sh`, port 8084): each document is cut into overlapping 1200-character pieces, a document's meaning score is its best piece's cosine to the query, and the BM25 and meaning rankings are fused by reciprocal rank (k = 60). A document found only by meaning shows its closest piece as the snippet. If the embedder fails, search is BM25 only. A missing folder raises `FileNotFoundError`; `..`, `~` or an absolute path raises `WorkspacePathError` (a ValueError).
- `jobs.py`: `JobStore(db)`, table `jobs(id, kind, instructions, folder, status, created_at, finished_at, result_kind, raw_result, summary, approval_id INTEGER, error, model_log, release_status, released_text, topics)`. Status `queued, running, waiting_for_approval, done, refused, failed`; release status `none, releasing, shared, waiting, refused`. Methods: `create(kind, instructions, folder) -> id`, `start`, `set_status`, `set_kind`, `add_model_step`, `finish(job_id, raw_result, result_kind, summary=None, topics=())`, `job_for_result(kind, instructions, raw_result, result_kind) -> id` (a finished job written as status `done` in one insert, so it never counts toward MAX_ACTIVE_JOBS; the connector uses kind `search` for search_documents results; returns the newest identical job instead, same kind, instructions and raw_result and not failed, while its release status is none, releasing or waiting), `fail`, `set_release(job_id, status, approval_id: int | None = None, released_text=None)`, `get(job_id) -> dict | None` (model_log and topics decoded, approval_id an int), `list_recent(limit=20)`, `claim_release(job_id) -> bool` (none to releasing; one caller wins), `reset_release(job_id)`, `fail_unfinished(error) -> int` (queued and running jobs become failed with "The device restarted before the job finished.", releasing goes back to none; Services.create calls it), `active_count()`. `set_release` moves a finished job to `waiting_for_approval`, `refused` or `done`; a failed job stays failed. `error` holds fixed messages only, never exception text.
- `agent.py`: `Agent(settings, llm, index, jobs, heavy=None, roster=None, tagmap=None, restore=None)`. `run_private_task(instructions, folder) -> job_id` starts a daemon thread, or raises `AgentBusy` when `MAX_ACTIVE_JOBS` (5) are queued or running; jobs take one model slot at a time on the device, two on the cloud backend. `run_sync` finishes first. `stop()` makes queued model steps fail at once (Services.close calls it). It stores Muse's tag-only instructions and restores tags locally only to choose what to do. The model gets Muse's instructions with their tags and every document, title and rubric with roster names, known tag-map values and identifiers swapped for the same tags; its answers are restored to real names on the device. It grades when the instructions mention grade/feedback/score/rubric and a `rubric.md` is in the folder or the nearest parent folder inside the workspace root (`demo/rubric.md` for `demo/essays`). Grading: one strict-JSON step per essay (`grade:<n>`, scores 1 to 4 for ideas, organization, evidence, conventions, total recomputed), all grades before any file, then `<Student Name> feedback.md` (0600) under `settings.paths.output / job_id`, a raw per-student table with real names for roster students and `Essay N` for anyone the roster does not know (`per_student`, topics `grades, writing`) and a class summary with names scrubbed. Otherwise map per document then reduce (`free_text`, no summary). Up to 4 steps at once on the cloud backend, 1 locally. `model_log` entries are `{step, model, backend, device, latency_ms, via: local|heavy}`. Emits `working`, then `idle` when no job is left.

## Regions sidecar (`sidecars/sam/`)

Meta's SAM 3.1 on this device behind a small HTTP server, so faces, signatures, ID cards and barcodes in a page image can be found and covered before the local reader sees the page. It has its own uv project (`sidecars/sam/pyproject.toml`: mlx-vlm, pillow, fastapi, uvicorn; `exclude-newer` set to Oct 16 keeps the lock to releases at least two weeks old), so the root project never imports mlx. As of Oct 31 nothing is locked or installed and no weights are on disk; the mlx predictor is unverified (see `sidecars/sam/README.md`). The device side that calls it is in Regions on the device, below.

- Start: `scripts/start_sam.sh`, which does nothing unless `SAM_ENABLED=1` (default off). `scripts/start.sh` runs it when `SAM_ENABLED=1` as an optional child: it starts before the app, the app does not wait for it, then start.sh waits up to 180 s for its `/health` and says whether it came up (log in `BASE_HOME/logs/sam.log`). Its pid is in `OPTIONAL_PIDS`, not `PIDS`, so it stopping never stops the app; images are then not read (fail closed) until it is back. `SAM_URL` (default `http://127.0.0.1:8085`, read through `Settings.sam_url`) must be loopback; `SAM_MODEL_DIR` (default `models/sam3.1-mlx`) must hold the weights' `config.json` and `sidecars/sam/.venv` must exist, or it prints what Ethan would run and exits without downloading or installing anything. It sets `HF_HUB_OFFLINE=1` and runs `python -m sam_server --host 127.0.0.1 --port <SAM_URL port> --model-dir ... --model <SAM_MODEL_ID, default mlx-community/sam3.1-bf16> --key-file BASE_HOME/llama_api_key`. `sam_server.main` refuses any host but 127.0.0.1, ::1 or localhost, and a missing or empty key file.
- `GET /health` (no key): `{ok: true, model, backend: "mlx" | "fake", prompts_version, concepts}`. A caller treats `backend: "fake"` as no checker.
- `POST /regions` with `Authorization: Bearer <key>` (the key in `BASE_HOME/llama_api_key`, compared in constant time; 401 otherwise). Body over 8 MB, by Content-Length or while streaming: 413. JSON body: `image_b64` (PNG or JPEG, at most 40 MP), `concepts` (default all of `face`, `signature`, `id card`, `barcode`), `threshold` (0 to 1, default 0.3), `pad` (0 to 64 px, default 8), `cover` (default true). A bad body is 400 with a fixed `{error}` that never repeats the input. Reply: `{width, height, model, prompts_version, regions: [{kind, concept, score, box: [x1, y1, x2, y2]}], counts: {kind: n}, pad, covered_png_b64, ms}`. Kinds are `face`, `signature`, `id_card`, `barcode`; boxes are pixels with x2 and y2 exclusive, clipped to the image. `covered_png_b64` is the page with each box grown by `pad` (clipped) filled solid black, a box fill rather than the mask so it fails safe; it is left out with `cover: false`. A model error is 500 with fixed text, and the log gets the exception's type name only.
- One check at a time behind a lock. The image is never written to disk or logged: the one log line per request is the counts and milliseconds.
- Predictors (`find(image, concept, threshold) -> list[Region]`): `MlxSamPredictor(model_dir, model)` imports mlx-vlm only when built and sends each concept's prompts (`PROMPTS`, `PROMPTS_VERSION` "v1"; barcode also asks for "qr code"), keeps boxes and scores above the threshold (`regions_from_output` accepts pixel or 0 to 1 boxes) and drops a box that repeats a better one of the same kind (IoU 0.7). `FakePredictor(truth_path)` answers from `eval/sam_pages/truth.json` by matching the decoded pixels to a page, score 1.0; any other image has no regions. Tests use only the fake (`tests/test_sam_server.py`, `tests/test_regions.py`).

## Regions on the device (`base/regions.py`)

With `SAM_ENABLED=1` (and `CHECKER_BACKEND=lfm`, so images are documents at all), every page image is covered by the sidecar before LFM3-VL-2B reads it, and an image the sidecar cannot check is not read. Off by default: with `SAM_ENABLED` unset nothing here runs and images are read as before.

- `RegionClient(settings, *, client=None, allow_fake=False)`: httpx with `trust_env=False`, 60 s timeout (connect 5 s), refuses a non-loopback `sam_url`. The key is `settings.checker_api_key` (the same `BASE_HOME/llama_api_key`). `check(image_bytes) -> Regions(sha, counts, boxes, model, prompts_version, covered)`. A cache hit makes no call. Otherwise it first needs `GET /health` to say `ok` with backend `mlx` (a good answer counts for 60 s; `backend: "fake"` is refused unless `allow_fake`, which only tests pass), then `POST /regions` with all four concepts, `pad` 8 and `cover: true`. Counts are recomputed from the regions; every kind must be known, every box inside the page, and the covered copy a PNG the size of the page. Anything else (no key, down, slow, 4xx/5xx, a bad reply) is `RegionError` with the fixed text `UNCHECKED`. After the sidecar was down or slow (an httpx transport error), every check fails at once for 30 s instead of waiting again; an error status or a bad reply fails that image only. `available()` (the Controls page) is a 2 s health check.
- Cache, under `BASE_HOME/regions` (0700): `<sha>.json` (`version` 1, `counts`, `boxes`, `model`, `prompts_version`, `pad`; no pixels) and `<sha>.png` (the covered copy, never the original), both 0600, written atomically, the PNG first. `read_record(folder, sha)`. Retention deletes both (`retention.purge`).
- `ScanReader(settings, llm, *, regions=None, controls=None)` (`base/workspace/scans.py`): with a client, the vision model gets only `Regions.covered`, and the text ends with `covered_note(counts)` ("Covered on this device before reading: 2 signatures and 1 photo of a person.", or "Checked on this device before reading: no faces, signatures, ID cards or barcodes found."). That text is cached as `<sha>.covered-v1.txt`, so a `<sha>.txt` read without covering is never reused. The check runs before the cached text is used (a cache hit when the record is there), so every covered reading has its record. A `RegionError` becomes `ScanError(UNCHECKED)` with no model call and nothing cached; the index already skips an image that raises, so it is in no search, passage, ask or task, and `index.read` raises. Under the `cui`, `cjis` or `export` toggle (or a broken controls file, which reads as every toggle) SAM is never called: the SAM License excludes ITAR and military end uses, and those toggles already keep every result on the device, so the page is read as it is under the plain `<sha>.txt` name.
- Saying so: `unchecked_images()` is a context manager that collects the images the reader left out (`note_unchecked`, in memory only). `search_documents` (base/connector/server.py) and `DeviceAsk.run` (base/workspace/ask.py) add `unchecked_note(n)` ("2 images were not read, because the device could not check them for faces and signatures first.") to what they return. A `run_private_task` that hits one fails with the same fixed `UNCHECKED` text (`agent.short_error`).
- Lookups for egress and the page: `image_sources(sources)`, `image_check(settings, sources) -> ImageCheck(counts, checked, unchecked) | None` (None when no source is an image; an image whose current bytes have no record counts as unchecked, so a changed or missing file is unchecked), `covered_png(settings, doc_id) -> Path | None` (only files in `BASE_HOME/regions` with a record), `workspace_file(settings, doc_id)` (inside the root only), `describe(counts)`.
- Egress, only with `SAM_ENABLED=1` (otherwise receipts and floors are unchanged): for every kind but `document_list` (a listing never reads an image), `image_check` on the release's sources. The receipt gets `image_regions` (kind to count) and `images_unchecked`, and its `checks` gain `image check` when at least one image was checked. No box, pixel, file name or hash is in the receipt. With `SAM_ENABLED=1`, an image source with no record refuses the result (floor `regions:unchecked`, "Kept on your device. It came from an image the device has not checked for faces and signatures."), unless a toggle already refuses it with its own reason. `compliance.check(..., image_kinds=counts)`: see Compliance toggles.
- Approval page: `GET /scan-preview/{decision_id}/{n}` serves the covered PNG for the n-th image source of that decision row (`sources`), behind the same access as every page (a session off loopback). 404 for a deleted row, a bad index, a source that is not an image or has no covered copy. It never reads anything but `BASE_HOME/regions/<sha>.png`. The approval card shows each covered page as a thumbnail with "Covered on this device before reading. The covered page stays on this device: Muse gets text only, never the image." History's receipt has an "Image check" line, `/api/audit.csv` an `image_regions` column (`kind=n;...`), and the Controls page one line while `services.regions` is set and its sidecar is not answering.

## Privacy controls (`base/controls.py`)

- Set on the approval page's Controls tab (GET `/controls`, POST `/api/controls` as a form or JSON, GET `/api/controls`), kept in `BASE_HOME/privacy_controls.json` (0600), re-read when the file changes; a broken file means the default, which tags everything. `Services.controls` is the `ControlStore`.
- `Controls(tag_kinds, always_redact, never_redact, names_off_folders, hidden_folders)`. `tag_kinds` covers phone, email, address, dob and student_id; SSNs and card numbers are always tagged. Folders are top-level names, `.` for the files at the top of the workspace.
- `Controls.redaction(sources) -> guard.Redaction | None`: `guard.Redaction(skip_kinds, names, always, never)` is passed to `guard.tag` and `guard.leaks` (the final check), so both agree. `always` words become `[Redacted N]` tags (kind `term`, also in `TAG_RE` and restore); `never` words are left as written wherever they occur, except inside an SSN or card number; always wins over never. Names are left as written only when every source of the result is in a names-off folder (then the model name pass is skipped too); no sources or mixed sources tag everything.
- Egress: `release(..., sources=())` sets the redaction for that release (a context variable), and the decision row keeps `sources` (column added on open), so `resolve` after the user's OK checks with the same controls. The connector passes the listed documents (list_documents), the picked passages (search_documents), `AskRunner.sources` (ask_device) and the job folder (run_private_task); a job whose sources are unknown after a restart tags everything.
- `hidden_folders`: `DocumentIndex(controls=...)` skips every file in them, and `resolve` raises `FileNotFoundError` for a hidden folder, so list, read, search, passages, ask_device and tasks all lose them.

## Compliance toggles (`base/compliance.py`)

Several can be on; the strictest rule wins. A toggle needs `DEVICE_ONLY=1`: `/api/controls` and `/api/setup` answer 400 without it, and if one is set anyway, egress keeps every result on the device (floor `compliance:cloud`). A broken controls file reads as every toggle on.
- Tagging: `guard.Redaction.extra_kinds` adds `place`, `date`, `detail`, `record`, `url` and `ip`, plus `age` (over 89) under HIPAA. `guard.leaks` checks the same kinds. The name pass uses `llm_details`, which also finds places and organizations. Default output does not change when no toggle is on.
- Locks: while a toggle is on, `Controls.redaction` ignores identifier opt-outs, never-redact words and names-off folders (the file keeps them), and egress ignores Always approve. `/api/auto-approve` answers 409 for on.
- Holds, after the router and again on a summary (`compliance.check`), first match wins: a `local_only` toggle (`cui`, `cjis`, `export`) refuses every result (floor `compliance:local_only`); a toggle's `keep_words` refuse (`compliance:sensitive`); fewer than `SMALL_GROUP_MIN` (10) people refuses (`compliance:small_group`); with `image_kinds` from the SAM check, a face under `hipaa` or `coppa` (`FACE_TOGGLES`) gives ask_user (`compliance:face`, `FACE_REASON`) and a signature under `hipaa`, `legal` or `hr` (`SIGNATURE_TOGGLES`) gives ask_user (`compliance:signature`); a source that is an image gives ask_user (`compliance:scan`); `ask_words` give ask_user (`compliance:ask_word`); `ask_all` gives ask_user (`compliance:ask_all`). Keywords are checked on the raw text as well, since one can sit inside a tag.
- `/ask` answers a question with the device's model only (`ask_runner`, no egress), showing real names on the page. It is how a `local_only` user gets answers.
- Retention (`base/retention.py`, docs/RETENTION.md): `retention_days` (90 under COPPA and GDPR), run at most hourly from the release path. It deletes old decisions, jobs and files in `output`, `scans` and `regions`.
- No page may say "compliant". Each profile's `limit` is shown next to its toggle.

## Router (`base/router.py`)

With `DEVICE_ONLY=1` and LFM, no model decides: a rule the user taught, else the first matching policy rule, gives the decision (`source="rule"`). Practice defaults only count as floors, never as permission to share. The model only labels who a request is for. More floors apply there: a `sensitive_record`, a request for contact details (floor `contact`) and a request that picks out one person by what makes them unique (floor `narrowed`) are refused, and a request that names a destination outside the class gives ask_user (floor `outside_class`) unless a rule the user taught shares results like this. A router that could not decide (`source="fallback"`) is never answered by Always approve.

- `Router(settings, llm, policy, rules_text=None, adapter=None)`, `decide(inp, *, synthetic=False) -> RouteDecision`. `rules_text=None` re-reads `settings.paths.router_prompt` on every call.
- Rule path, no model call: `document_list` with a `person` hit (the name pass found someone the roster does not know) asks the user; otherwise `document_list` and `dreaming_report` share tagged; a policy rule marked `pre_approved` (matched on request, kind and topics) when nothing is blocked. Otherwise one strict-JSON call (`ROUTE_SCHEMA`, reasoning low, 1500 tokens) with the system prompt, the learned rules and the RouteInput (hit kinds only, real values scrubbed, text cut at 1500 characters).
- Floors on every path: a blocked reason or a never-share topic of the result -> `refuse`, or at least `ask_user` when every blocked topic is in `ask_first` (`never_share_floor(blocked, blocked_topics, ask_first) -> refuse | ask_user | None`, which egress also uses); a never-share topic only in Muse's request (`request_blocked`) -> at least `ask_user`, never `refuse` by itself, since "Do not mention any IEP" is a caution, not a question; an identifier hit -> at least `ask_user`; a model or parse error -> `ask_user`, source `fallback`. Also: a long digit run (`guard.long_digit_runs`) in anything but `class_aggregate` and `dreaming_report` -> at least `ask_user`; every policy rule that wants `refuse` and matches the request, kind and topics -> `refuse` (a rule over never-share topics only is the blocked floor already); the learned floor (`train.learned_floor`, below) -> at least its decision. When a floor decides the result, its fixed reason replaces the model's. Floor labels: `blocked:<topic>`, `ask_first:<topic>`, `request:<topic>`, `identifier:<kind>`, `identifier:digits`, `policy:<rule id>`, `learned:ask_user`, `learned:refuse`, `blocked`, plus egress's `summary`, `name_check` and `topic_check`.
- Learned rules (the dreaming file, keyed with `train.rule_key(kind, topics, relevant_topics(policy))`): the model is shown the one rule that fits best (`train.match_rule`) on a "Learned rule for this result" line. The learned floor is computed apart from it: the strictest `ask_user` or `refuse` rule among the shown rule and every rule that covers the result (`train.covers`: a rule for the same kind whose topics are a subset of the result's, `topics: none` included, or a matching `(topic: X)` rule), counting your rules first and practice defaults only when none of your rules covers the result. So a topic Muse's request adds (`class_level`, `parents`) can move a result to a narrower group but never out from under a broader ask first or refuse rule, and a closer share rule never loosens one. When the floor's rule is not the shown one, the model also gets a "Learned rule that also holds" line, and the system prompt's step 3 says to follow it.
- `build_user_message(inp, learned=None, also=None)`. `Router.learned(inp, rules=None) -> (shown, floor)`, each a `train.RuleLine` or None; `Router.learned_rule(inp)` is the shown one. `Router.learned_view(inp, rules_text=None) -> LearnedView(shown, floor, floor_decision, floor_source)`, a hashable NamedTuple of the shown rule line, the floor's rule line, its decision and its section (`user` or `synthetic`): everything the learned rules add to one decision, for the given rules text (default: the router's own), so the gate can compare two rule files item by item. router.py imports `base.dreaming.train` and `base.guard`.

## Approvals (`base/approvals.py`)

- `ApprovalStore(db_path)`, SQLite WAL behind one lock. Table `decisions(id, ts, day, job_id, tool, request, result_kind, topics, blocked, tagged_text, shown_form, router_decision, router_reason, router_source, status, user_decision, remember, decided_by, decided_at, deleted, item_id)`. Ids are ints. `blocked` is a JSON list of plain reasons from `TagResult.blocked`; the approval page shows it as is. Older dbs get the column on open.
- `record_auto(**kw) -> id` and `create_pending(**kw) -> id` take keywords `tool, request, result_kind, tagged_text, router_decision` and optionally `router_reason, router_source, topics, blocked, shown_form, job_id, day (default today(): days since 1970-01-01), item_id`. `decide(id, approve, remember=False, by="user"|"policy_sim")` returns the row; `KeyError` for no row, `ValueError` if it is not pending or was deleted. `get`, `pending()`, `history(limit=50)` (both skip deleted rows), `delete(id)` (deleted=1, request and tagged_text blanked), `training_rows()` (decided, not deleted, with `label`), `counts_by_day()` (rows that were not auto, per day), `close()`.
- `label_for(row)`: approve + remember -> `shown_form`; deny + remember -> `refuse`; no remember -> `ask_user`; undecided -> None.
- The approval page shows the exact tagged text, the router's reason, the blocked reasons, Share it / Keep it here and the remember box.
- Always-approve mode (`AutoApprove(settings.paths.auto_approve)`, a 0600 file in BASE_HOME, switched on the approval page with POST `/api/auto-approve {on}`, same-origin like every POST; `/api/status` reports `auto_approve`): egress still creates the pending row for an `ask_user` result, then decides it at once with `by="auto_approve"`, no remember, and returns it shared. Refusals, held results and the final leak check are unchanged. `training_rows()` leaves auto-approved rows out, so dreaming never learns from them.

### Policy (`base/policy.py`, `eval/user_policy.yaml`)

`UserPolicy.load(path)` (or `from_dict`), `PolicyError` naming the file and field. Top-level keys `name, description, never_share, ask_first, request_topics, rules, default`; rule keys `id, kinds, topics_any, topics_all, request_any, wants, pre_approved, on_ask, note`. First match wins, else `default`. `ask_first` topics must be in `never_share`; `pre_approved` only with a share form; a rule without `on_ask` answers the way its `wants` implies.

```yaml
never_share:            # topic -> keywords; guard.blocked_topics uses these
  iep: ["IEP", "504 plan", "individualized education", "special education", "speech therapy", "accommodation plan"]
ask_first: []
request_topics:         # topic -> plain description; Glimmer labels Muse's request with these
  parents: "meant for a student's family: parents, guardians, a note or letter home, a family newsletter"
  class_level: "asks for class-level numbers or patterns (an average, a count, a trend)"
rules:
  - id: class_averages
    kinds: [class_aggregate]
    request_any: ["average"]
    wants: share_summary
    pre_approved: true
    on_ask: {approve: true, remember: true}
default: {wants: ask_user, on_ask: {approve: false, remember: false}}
```

`match(item) -> Rule`, `wants(item)`, `answer(item) -> (approve, remember)`, `pre_approved(kind, topics, request="")`, `never_share -> dict`, `ask_first -> set`, `request_topics -> dict[str, str]`. Request topic names are lowercase words and may not repeat a never-share topic; descriptions are whitespace-collapsed. `item` is any mapping or object with `request`, `result_kind`, `topics`. For every eval item `expected == policy.wants(item)` (tested).

### Egress (`base/egress.py`)

`Egress(services, guard=None)`. `release(tool, request, raw_text, result_kind, *, job_id=None, summary=None, topics=(), item_id=None, day=None, synthetic=None) -> Released(status, text, approval_id, decision, tag_result, retryable=False)`, status `shared | waiting | refused`.
- `synthetic=None` means: True only on a cloud backend whose workspace root is marked `.synthetic`. The eval passes True.
- Tagging calls `guard.tag` with `llm_names=functools.partial(answer_llm.llm_names, synthetic=...)` for every kind except `dreaming_report` (`NO_NAME_PASS`; document titles and paths get the pass). If tagging or the name pass raises, the result is held: "Held on your device.", decision refuse with floor `name_check`, audit `name_check_failed`, no decision row, and `Released.retryable` True. A summary the model could not write is held the same way (audit `summary_failed`). Muse's `request` is tagged with the roster pass (no model call) before it is routed or stored, and its identifier hits (an address, a phone) join the RouteInput's `hits`, so they floor at least `ask_user`. If tagging the request raises, the result is held like a failed topic pass (below); it is never routed on a withheld request.
- Request topics: never-share keywords found in Muse's request (`guard.blocked_topics` on the raw request, a local regex on the device whose input is never stored or sent, plus the tagged request, so "1200 Oak Avenue", tagged `[Address 1]`, still counts), plus `answer_llm.request_topics(request, policy.request_topics)` on the tagged request for every kind except `document_list` and `dreaming_report` (`NO_TOPIC_PASS`). The model pass is also skipped when the result's own never-share topics already make the floor refuse (`router.never_share_floor`), since its labels could not change the outcome. Both join `topics` and the result's own keyword topics in the RouteInput and the decision row. A never-share topic found only in the request (not in the result or the passed `topics`) also goes in `request_blocked`: an `ask_user` floor `request:<topic>`, so "Which students have an IEP?" over a list of tags asks the user even though the answer has no keyword, and the floor never refuses "Do not mention any IEP" by itself (the router model, a policy refuse rule or a learned refuse rule still can). Module helpers, also used by `scripts/cloud/quant_eval_modal.py` so its lookups match: `request_keyword_topics(raw_request, tagged_request, never_share, scan=None)`, `needs_topic_pass(result_kind, tagged, own_topics, policy) -> bool` and `route_input(asked, result_kind, tagged, own_topics, asked_about, never_share, summary=None) -> RouteInput` (hits are the result's plus the tagged request's identifier hits; topics are `own_topics` then `asked_about`). If the model pass raises, the result is held like a failed name check: floor `topic_check`, audit `topic_check_failed`, no decision row, `retryable` True. The row's `shown_form` is `default_share_form(kind, topics)`.
- Then route, record one decision row (with `blocked`), and return. `share_summary` (and `ask_user` whose shown form is a summary: `class_aggregate`, or a `class_level` request) shares the tagged `summary`, or one the answer model writes from the tagged text; a summary that still has a `[Student X]` or `[Person N]` tag is refused.
- `resolve(approval_id: int) -> Released`: pending -> waiting, approved -> the stored tagged text, denied or deleted -> "Kept on your device.". `approval_id` is set for waiting rows and resolve results only.
- Texts to Muse: "Waiting for your OK on the device.", "Kept on your device. <one fixed sentence for the floor that kept it>" (`refusal_text(floors)`; the router's own reason is model text and stays on the approval page), "Held on your device.". After a shared result egress emits `sending`, then `waiting` or `idle`. Every one passes `final_check(text) -> list[Hit]` (`guard.leaks`; fails closed).

### Services (`base/services.py`)

`Services.create(settings, *, light=True, heavy=None)` wires one of each: `settings, events (base.events), roster (guard.load_roster), tagmap (TagMap.for_settings), policy, answer_llm, router_llm (LocalLLM roles), router, approvals, jobs, index, heavy (HeavyQueue on paths.db with wait_seconds=HEAVY_WAIT_SECONDS=120 when settings.heavy_queue, else None), agent (with heavy), audit (connector.audit.Audit on paths.db), egress, night (NightRunner), light (start_light)`. `Services.create(..., owner=True)` also fails jobs a stopped process left unfinished, tells `events` how many approvals are pending, and on llama_server with `DREAMING_BACKEND=lora` finds the router adapter's id (`GET /lora-adapters`, the entry ending in router.gguf) for `Router(adapter=...)`. `Services.for_eval(settings)` is the same with no light, no heavy queue, `owner=False` and a `QuietEvents` bus, so a night never drives the light or the page; `eval/run_eval.py` and the dreaming gate use it. `close()` stops the agent's model steps and the light and closes the store and model clients. Modules that need others take a `services` object; tests pass a `types.SimpleNamespace` with only what they use.

`python -m base` (or `python -m base.server`) builds Services, the approval page and the connector, and runs both uvicorn servers in one loop until Ctrl+C or SIGTERM, then closes Services. httpx request logging is turned down so no model or worker URL is logged.

## Connector (`base/connector/`)

- `server.py`: `connector_app(services, *, token=None)` is the MCP server (official `mcp` SDK, streamable HTTP, stateless, JSON responses) at `/mcp` plus `GET /health` without auth, served on 127.0.0.1:8790. Every other path needs `Authorization: Bearer <token>` from `settings.paths.connector_token` (made 0600 on first use). The SDK only accepts Host headers 127.0.0.1 or localhost. A standalone GET stream gets 405.
- Tools and annotations (Muse classes tools Read, Write, Sensitive write):

| Tool | Muse class | Input | Returns |
|---|---|---|---|
| list_documents | Read | folder | tagged titles and relative paths, through egress. A title or path with a never-share keyword is left out and counted: "N documents held back on the device." |
| search_documents | Read | query (tags restored locally), purpose (optional, never searched) | up to 5 snippets of 300 characters, through egress, as plain text when shared or refused; `{job_id, status: "running" \| "waiting", result}` when the check needs more time or the user's OK (see Search releases below) |
| ask_device | Read | question (tags restored locally), purpose and folder (optional; a hidden or missing folder is a plain error) | mode 2, a background job: `{job_id, status: queued, result}` at once; get_result releases it (job kind `ask`, decision rows name `ask_device`). `AskRunner` (`base/workspace/ask.py`, one job at a time on the checker, MAX_ACTIVE 5, `AskBusy` past that) runs `DeviceAsk.run` for up to 180 s: split the request into up to 5 standalone parts; per part, rewrite queries, rank passages for every query so far (`index.passages`), show the checker up to 12 tagged passages with the question last, and while nothing is found search again with the model's or newly written queries, up to 3 rounds; a part whose answer touches a never-share topic is held (`HELD_PART`) before combining; answered parts are combined by the checker, then fixed sentences say how many parts were held, not answered or not reached. | run_dreaming | Write | none | `{job_id, status}`, the same job while one runs (not idempotent: a call after a night ends starts another) |
| dreaming_report | Read | none | aggregate numbers only, through egress, with "A dreaming run is in progress." first while one runs |
| | | | A run_private_task above MAX_ACTIVE_JOBS gets one sentence with the count (audit `busy`). |

- Saying what a result is for: INSTRUCTIONS and the run_private_task and search_documents descriptions ask Muse to say who a result is for and what it will be used for ("for my own grading", "for the family newsletter", "to send to the principal"), in run_private_task's instructions and in search_documents' `purpose`, so egress's request topics have something to read.
- Search releases: the request egress sees is the query, or `"<query>\nPurpose: <purpose>"` when a purpose is given (tagged and labeled like any request; only the query is searched). The snippets become a finished job, `jobs.job_for_result("search", request, raw, "snippet") -> job_id` (kind `search`, status `done` at once, so it never counts toward MAX_ACTIVE_JOBS; the raw snippets stay in `raw_result` on the device), and are released by the same claim, thread and `RELEASE_WAIT_SECONDS` wait as get_result, with tool `search_documents` on the decision row (`RELEASE_TOOLS`). Past the wait the answer is `{job_id, status: "running", result: SEARCH_CHECKING_NOTE}` (audit `pending`); a waiting release is `{job_id, status: "waiting", result}`; Muse follows either with get_result. While a job with the same kind, request and raw result is unreleased, releasing or waiting, `job_for_result` returns it, so a retried search joins that release and never makes a second release or approval card; once it is shared or refused, the same search later is a new job with its own check.
- Failures reach Muse as one plain sentence. Audit outcomes: `shared, waiting, refused, started, pending, failed, bad_input, busy, error, cloud_refused`; egress adds `egress_blocked`, `name_check_failed`, `topic_check_failed` and `summary_failed`.
- `audit.py`: `audit(db, tool, outcome, ms=0)`, `recent(db, limit=50)`, `Audit(db)` callable as `services.audit(tool, outcome, ms=0)`, table `audit(ts, tool, outcome, ms)`. Labels must be short lowercase words; never content.
- `relay_client.py`: dials out to `RELAY_URL` over WebSocket with the device secret, forwards each JSON-RPC message to the local MCP server, returns responses. Reconnects with backoff. `python -m base.connector.relay_client pair` asks the relay for an 8 character one-time pairing code (single use, 10 minute expiry) and prints it; `unlink` revokes every Muse link. A cleartext RELAY_URL is refused unless it is loopback. `run` exits 3 (the unit's RestartPreventExitStatus) when the secret is rejected or another copy took over.

## Relay (`relay/`, Cloudflare Worker, TypeScript)

- Worker + one Durable Object per device. Device endpoint `GET /device/connect` (WebSocket, `Authorization: Bearer <device secret>`), `POST /device/register` (returns device id + secret once), `POST /device/pair` (device asks for a pairing code). `POST /device/unlink` (bearer secret) revokes every OAuth grant bound to the device and returns `{"revoked": n}`. Muse endpoint `POST /mcp` (streamable HTTP, OAuth bearer), OAuth via `@cloudflare/workers-oauth-provider` with dynamic client registration; the authorize page asks for the pairing code, which binds the grant to that device. The relay stores no tool content; it forwards bytes and keeps only device ids, hashed secrets and grants.

## Dreaming (`base/dreaming/`)

- `dataset.py`: `build(store, synthetic_path, holdout_ids=()) -> list[Example(request, result_kind, tagged_text, label, weight, topics, source, approved, remember, row_id, item_id)]`. User rows weigh 3, synthetic rows 1. Skips deleted rows and holdout ids. Labels come from `approvals.label_for`.
- `train.py`: `train(examples, settings, backend=None, *, out_path=None, day=None, policy=None) -> TrainResult(backend, path, rules, examples, user_examples, cloud_required, message)`. Backend `prompt` (default) groups examples by `rule_key(kind, topics, relevant_topics(policy))` (relevant topics: never-share topics, request topics and every rule's topics) and writes one rule line per group with exact counts, plus strict topic rules `(topic: X)` that need evidence of their own, from scratch each night (deterministic, no model call). A group with a never-share topic the floor refuses (`floored_topics`) gets no practice rule, and only an ask first or refuse rule from the user's own decisions: a result with such a topic in its own text is refused without a card, so the user only answers when Muse's request alone names it (floor `request:<topic>`), and a learned refuse rule then lifts that ask to `learned:refuse`; a share rule there would change nothing, so none is written. The header says so: such a topic in a result's own text is always refused, one named only in Muse's request is asked about unless a refuse rule holds. `read_rules(text) -> list[RuleLine(kind, topics, decision, source, text)]`, `match_rule(rules, kind, topics)` (the one rule shown: your exact group, else your strictest topic rule, else the same from the practice defaults) and `learned_floor(rules, kind, topics) -> RuleLine | None` (the strictest ask first or refuse rule among the match and every rule that `covers(rule, kind, topics)` the result: same kind with a subset of its topics, or a topic rule for one of them; your rules first, practice defaults only when none of yours covers it) read them back for the router. The file's header says the same: the best-fitting rule is shown, and an ask first or refuse rule also holds for every result of its kind that has all of its topics, with or without more. Backend `lora` writes `adapters/train-<date>.jsonl` and says to run `scripts/cloud/train_lora_modal.py`; it never launches it. In that file a row the user did not approve has its request and text withheld, and a row in which `guard.leaks` (roster and tag map) still finds anything is left out; with no roster or tag map nothing is written.
- `gate.py`: `gate(services, candidate_rules_path, current_rules_path, holdout_items, *, force=False) -> GateResult(keep, before, after, reasons, rerun)`. Paired, so run-to-run flips on a few items cannot reject a good night: the current rules are scored once with `run_eval.evaluate` on the holdout in a fresh temp home; `changed_items` then compares `services.router.learned_view(inp, rules_text)` under the current text (`""` when there is no current file) and the candidate text for each item's RouteInput from that run, and the candidate is run, in another fresh home, only on the items whose view differs, plus any item the current run could not route (it raised, or a check held it before the router: no RouteInput). Every other item reuses the current run's row (`reused: true` in the gate's raw rows), and `paired` merges them with `run_eval.rescore` into `after` (`name` gate-candidate). `rerun` is the number of items re-run. Services with no router that has `learned_view` re-run every item. This assumes a rule that is neither shown with an item nor behind its learned floor does not change that item's decision (the system prompt lists every rule, but step 3 makes only the shown ones binding, and the floor is in code). Keep only if overall accuracy, every category and agreement are no worse and leaks are 0 (a leak on a reused item counts against the candidate too), and neither side has more than 10% of items that errored or fell back (`MAX_UNSCORED_SHARE`), so a night scored while the model was down keeps the current rules. `force` replaces rules learned from since-deleted decisions as long as the candidate leaks nothing.
- `night.py`: `NightRunner(services, *, holdout_path=None, synthetic_path=None)`: `start() -> job id` (the running one if a night is going), `run_night() -> NightReport` (raises `DreamingBusy(job_id)`), `running_job()`, `wait(timeout)`, `last_report() -> dict` with `learned_from, accuracy_before, accuracy_after, agreement_before, agreement_after, kept, leaks, seconds, night_number` (night 0, learned_from 0 and None for the rest before the first night). Lock and history in tables `dreaming_lock` (with an `owner` of pid and a per-process token: a lock whose process is gone is not a running night) and `dreaming_nights`. `report_for(job_id)` gives one night's numbers. `NightReport.categories` holds holdout accuracy per expected decision; `NightReport.gate_rerun` is the gate's `rerun` (None when the gate did not run), and the note says "The gate re-ran N of M holdout items on the new rules". Neither is in `last_report()`. `synthetic_path=""` means no practice data; `raw_dir` (set by the simulation) gets each night's gate rows; `exclude_ids` (set by the simulation: its unseen test items) are left out of the dataset like the holdout ids, so practice data that contains them never teaches them.

## Heavy steps (`base/heavy/`)

- `queue.py`: `HeavyQueue(db_path, wait_seconds=30)` (Services uses 120), tables `heavy_steps` and `heavy_workers` in the device db. `run(kind, messages, schema, *, synthetic=False) -> dict | None`: None at once when no worker said hello in the last 30 s (or holds a claimed step), None after `wait_seconds` without a result. ## Cross-module details pinned on Oct 27

### Jobs and releases
The connector's `get_result` (and `search_documents`, through a `jobs.job_for_result` job of kind `search`) first claims the release (`jobs.claim_release`); a call that loses the claim, or finds release status `releasing`, answers `{status: "running"}` with "The device is still checking this result.". The winner runs the release on a thread and waits up to `RELEASE_WAIT_SECONDS` (40, under the relay's 55); past that it answers `running` and the release finishes in the background. A retryable release resets the claim and answers `running`, up to `MAX_CHECK_FAILURES` (3) in a row, after which it is stored as refused. The release itself calls `egress.release(RELEASE_TOOLS.get(job.kind, "get_result"), job.instructions, job.raw_result, job.result_kind, job_id=..., summary=job.summary, topics=job.topics)` (tool `search_documents` for kind `search`, so a search's decision row names the search) the first time a finished job is read and stores the outcome with `jobs.set_release(job_id, status, approval_id=int | None, released_text=...)`. While the release status is `waiting` it calls `egress.resolve(int(approval_id))` and stores the outcome once it changes. Shared and refused releases are resent from `released_text`. The approval page decides rows through `ApprovalStore.decide`; nothing is pushed to Muse.

### Heavy-step hook
The workspace agent takes an optional `heavy` object with `run(kind, messages, schema, *, synthetic=False) -> dict | None`. `None` means no laptop worker is available and the step runs on the device's own Glimmer; an exception does the same. The agent passes `synthetic=True` only for folders marked `.synthetic`. Services builds one `HeavyQueue` and shares it between the agent and the `/heavy` routes.

### Relay frames (relay/ and base/connector/relay_client.py must agree)
The device opens `wss://<relay>/device/connect` with `Authorization: Bearer <device secret>`. Frames are JSON text messages.
- Relay to device: `{"type": "request", "id": "<uuid>", "method": "POST" | "GET" | "DELETE", "headers": {"content-type": ..., "accept": ..., "mcp-session-id": ..., "mcp-protocol-version": ...}, "body": "<raw request body text>"}`
- Device to relay: `{"type": "response", "id": "<same uuid>", "status": 200, "headers": {"content-type": ..., "mcp-session-id": ...}, "body": "<raw response body text>"}`. If the local server answers with `text/event-stream`, the device collects the SSE `data:` lines for that request and sends them as one body with content-type `text/event-stream` (no long-lived streams in v1).
- Keepalive: either side may send `{"type": "ping"}`; the other answers `{"type": "pong"}`.
- Registration: `POST /device/register` with JSON `{"name": "<device label>"}` returns `{"device_id": "...", "secret": "..."}` once; the relay keeps only a SHA-256 of the secret. `POST /device/pair` with the bearer secret returns `{"code": "ABCD2345", "expires_in": 600}`, eight characters from an alphabet without 0/O/1/I, single use.
- The relay answers `503 {"error": "device offline"}` when no device socket is connected, and `504` after 60 seconds with no response frame.

### Approval page (review fixes)
Pairing codes: wrong codes are counted in `BASE_HOME/pairing_misses` across restarts; after 10 the server stops printing a code at start and only `POST /api/pair-code` from the device itself issues one (and clears the count). `POST /api/sessions/clear` signs out every other browser. The session cookie is Secure when TLS is on. uvicorn runs the approval port with `limit_concurrency=64`; a port that is already in use ends `python -m base` with one sentence and exit 3.
- Header names in frames are lowercase. The relay never logs bodies.
