# Decisions

| Date | Decision | Why |
|---|---|---|
| Oct 27 | Glimmer itself is the router | Glimmer's "assistant" model is a DFlash speculative-decoding drafter (model_type muse_glimmer_assistant, 5 draft layers), not a chat model |
| Oct 27 | Development runs Glimmer on OpenRouter (`meta/muse-glimmer-30b`) | Ethan asked for cloud only for now; the Mac has about 15 GB free. Cloud mode only reads folders marked `.synthetic` |
| Oct 27 | Jetson model is `mradermacher/Muse-Glimmer-30B-i1-GGUF` i1-IQ1_S (6.5 GB), IQ1_M (7.1 GB) as the comparison | Ethan asked to use a published quant instead of making our own; i1 files are imatrix quants of the base model |
| Oct 27 | No Jetson board is pulled from the fleet yet | Ethan's call; the Jetson path is tested in simulation |
| Oct 27 | The laptop dials out to the Jetson for heavy steps | The Mac is a managed work laptop that must not listen on the network |
| Oct 27 | Roster is 24 students, not 20 | The demo grades 24 essays, one per student |
| Oct 27 | Dreaming defaults to the prompt backend (rules rewritten each night); LoRA training is a cloud script | OpenRouter cannot load a LoRA adapter, and no local training |
| Oct 27 | The relay is new code in relay/ deployed as its own Worker | All work has to be in this repo |
| Oct 27 | The eval gives the router production inputs by default; hand labels only with `--oracle-labels` | Review finding: the connector never sends hand-labeled topics or the eval-only kinds, so labeled numbers overstated the shipped router |
| Oct 27 | A `.synthetic` marker counts only from the folder up to the workspace root | Review finding: a stray marker in a parent folder would have opened a real class folder to the cloud backend |
| Oct 27 | The simulation runs with no practice data by default; the practice run is an ablation | The practice set is labeled with the simulated teacher's own policy |
| Oct 27 | The device's model sees only tags in Muse's instructions and in the documents | Review finding: with real names in the prompt, an instruction could make it spell a name in a form no check knows |
| Oct 27 | t016 replaces t015 in the holdout | So the gate can see a leak of a name the roster does not know |
| Oct 27 | Glimmer's second pass for names runs on every result except dreaming reports, document lists included | The roster cannot know siblings, guardians or staff. It costs about one extra Glimmer call per result |
| Oct 27 | A result whose name pass or summary fails is held on the device ("Held on your device.") | Fail closed: no check, no release |
| Oct 27 | Learned "ask first" and "refuse" rules act as floors | Dreaming may only make the router stricter on its own; sharing more needs the model's call and the gate |
| Oct 27 | The relay accepts both dynamic client registration and client ID metadata documents | We have not seen which one Muse's client uses |
| Oct 27 | Pairing codes and client addresses are kept as HMAC-SHA256 under a Worker secret; at most 5 tries per code and 20 per address in 10 minutes | A copy of the relay's storage cannot be turned back into live codes, and a classroom behind one router can still pair several devices |
| Oct 27 | A second relay client with the same device secret stops the first (exit 3) instead of reconnecting | Two copies would otherwise knock each other off every second |
| Oct 27 | The practice set was written by Muse Spark 1.3 through the Meta Model API, not by Muse on its VM, and has no dreaming_report items | The plan's fallback. The teacher policy has no rule for dreaming reports. Ethan can redo the set in the Muse app and check it with `make_synthetic --check` |
| Oct 27 | On a Jetson the approval port can serve TLS with a self-signed certificate, which the laptop worker pins | The session cookie and the worker's essays would otherwise cross the home network in the clear |
| Oct 27 | At most 5 private tasks run or wait at once | A runaway caller cannot queue jobs without limit |
| Oct 27 | Every number we quote is cloud Glimmer on invented data until llama-server runs on a device | No local models on this Mac yet |
| Oct 27 | The demo's approval card is the tagged per-student table, not a class summary as the plan said | The connector sends grading results as per_student, and the router asks about per-student detail. A summary on the card is a product gap (`eval/reports/post_fix.md`) |
| Oct 27 | Final numbers live in `eval/reports/final*.md` and `eval/reports/final/`; earlier reports stay as they were | So the tuning and post-fix runs can still be compared |
| Oct 27 | The grading spot-check takes 10 of the 24 cloud-graded essays, evenly spaced by Glimmer's total | Covers weak to strong essays without hand picking |
| Oct 27 | The day-5 leak the eval's checker flagged in the final simulation stays in the record, explained, until the checker is fixed and the nights are rerun | A leak count is never edited after the fact, even a false positive (the verb "rose" matched the invented student Rose). Done: the checker was fixed (row below) and the rerun counts 0 day leaks (`eval/reports/final/nights.md`); the flagged run stays unchanged in `eval/reports/before_fixes/final/` |
| Oct 27 | No separate 100-task eval of the night-five router in the final runs | In the first final runs the gate kept no night's rules, so the night-five router was the starting router. In the rerun after the fixes it kept all five, so that is no longer true: the night-five router (`eval/reports/final/learned_rules_night5.md`) is scored by the holdout after night 5 and the unseen test, not by final_cloud. Done in the round after the guard fix: `eval/reports/final_cloud_night5_rules.md`, 88% with 35 approval requests and 0 leaks, $0.0979. It is in-sample (the holdout and the day items the rules learned from are among the 100), so the unseen test stays the learning number (`eval/reports/final.md`, section 3) |
| Oct 27 | The device labels Muse's request with the policy's request topics (Glimmer, one extra call per result) and scans it for never-share keywords | On production inputs the gate kept no night's rules: who a result is for ("for families", "send to the principal") appears only in the request, so one rule mixed shares, asks and refusals. On a held-out draw of invented requests Glimmer beat a keyword list on third_party and class_level, tied on deanonymize, traded recall for precision on parents (0.86 and 0.86 against 0.65 and 1.00), and over-labeled full_text (precision 0.50 against the keywords' 1.00, so a request for one paragraph can be treated as a full-text request) (eval/reports/request_topics.md) |
| Oct 27 | `reidentify` is not a request topic | It feeds a refuse floor, and its labels were unreliable: with the description that was tried, Glimmer's reidentify labels had precision 0.50 (3 of 6) and recall 0.30 on the held-out draw, 0.25 and 0.50 on the tuning sample, 0.17 and 0.50 on the eval tasks (`eval/reports/request_topics.md`, candidate rows; few labeled items: 10, 6 and 2). The router's first step still covers it |
| Oct 27 | An answer to a class-level request (`class_level` topic) is shown and shared as a summary | Approving a class average taught "share tagged" before, so dreaming could never learn share_summary from production inputs |
| Oct 27 | The eval's leak checker treats a one-word name that is also a common word like the guard does (counts only when capitalized) | "The average rose" was scored as a leak of the invented student Rose |
| Oct 27 | The eval sends a per_student item whose request has a grading word (grade, feedback, score, rubric: `agent.GRADING_WORDS`) as per_student with the grading job's topics (`TOPICS_GRADING`), and any other per_student item as free_text with no topics | That is the agent's trigger: it grades only when Muse's instructions match those words and the folder has a rubric (the eval's essays folder always has one), and only the grading job emits per_student, always with grades and writing. The old production mode stripped those topics, which production always sends. A first fix chose the path from the hand label instead, which sent t008, t010, t013, t054, t055, t057 and t060 (no grading word) as grading tables, which would have credited holdout t010 with a learned share rule production would not earn (review finding). Numbers from before this row used one of the older mappings |
| Oct 27 | A never-share keyword found only in Muse's request asks the user (floor `request:<topic>`) instead of refusing | Review finding: a caution like "Do not mention any IEP" or an incidental word like "Main Street" silently refused a harmless result. The cost: "Which students have an IEP?" over a list of tags now asks instead of refusing, unless the router model or a refuse rule refuses it. A never-share topic in the result itself still refuses. The user's answers on those cards teach dreaming: deny with "don't ask again" becomes a refuse rule for that kind and topic, which the router then holds as a floor (`learned:refuse`) |
| Oct 27 | A learned "ask first" or "refuse" rule holds for every result of its kind whose topics include the rule's own (`topics: none` covers the whole kind), and a `(topic: X)` rule for any result with that topic. The strictest such rule is the floor, your rules before practice defaults (`train.learned_floor`); the model is still shown the closest rule | Review finding: once request topics joined the rule key, an extra topic such as `class_level` moved a result into a group with no rule, so a taught refuse no longer held and the router could share a summary without asking. The cost: a broader ask first or refuse rule also holds over a narrower share rule the user taught, so a learned "share a summary" for class-level free text cannot take effect under a "free text, no topics: ask first" rule |
| Oct 27 | The device scans Muse's raw request for never-share keywords as well as the tagged one, adds the request's identifier hits to the router's input, and holds the result (retryable, floor `topic_check`) when the request cannot be tagged | Review finding: a keyword inside a tagged span ("1200 Oak Avenue" becomes `[Address 1]`) was lost, and a failed request tag skipped both checks. The raw request is read only on the device and is never stored or sent |
| Oct 27 | Egress skips the request-topic model call when the result's own never-share topics already make the floor refuse | The labels could not change the outcome, and a topic model that is down no longer holds a result that would be refused anyway |
| Oct 27 | search_documents releases its snippets as a finished job, with the same claim and 40-second wait as get_result. Past the wait, or when the user's OK is needed, Muse gets a job id to follow with get_result | Review finding: with the request-topic call, a search on a Jetson could run past the relay's limit. A retried identical search joins the same release, so it never makes a second approval card |
| Oct 27 | search_documents takes an optional `purpose`, and the connector's instructions ask Muse to say who a result is for, there and in run_private_task's instructions | Request topics need it: a search query alone ("garden quotes") does not say the snippets are for families. The eval's snippet items assume Muse fills it in (`eval/DATASET.md`); whether the Muse app does is untested |
| Oct 27 | The dreaming gate is paired: it scores the current rules once on the holdout and re-runs the candidate only on items whose learned rules differ (`Router.learned_view`), reusing the current run's rows for the rest | Scoring both rule files from scratch let a few run-to-run flips reject a good night: in the rerun at commit 8afe137, the same rules scored 85% and then 80% (in the round after the guard fix, 90% and then 85%). The cost: it assumes a rule that is neither shown with an item nor behind its floor does not change that item's decision |
| Oct 27 | The simulation also scores an unseen test: 100 practice items (seed 0, 25 per decision) that the days, the nights and the gate never see, leaving out the eval tasks, the holdout and the 420 items the request-topic check used | The gate selects on the holdout, so its gains are an upper bound. The unseen items are Spark-written and labeled with the simulated teacher's own policy, so they are not a real teacher either |
| Oct 27 | The request-topic check's held-out numbers come from a fresh draw (seed 11) made after the descriptions were frozen; the earlier seed-7 sample and the eval tasks are reported as seen, and the 20 holdout items are counted once | Review finding: the "held out" sample had been shown during tuning, and the holdout was counted twice |
| Oct 27 | Muse Spark 1.3 grades the same 24 tagged essays as a second opinion (`scripts/grade_crosscheck.py`), not as ground truth | Ethan's spot-check is still the grading-quality number; two Meta models agreeing does not make either one right |
| Oct 27 | The first final runs moved unchanged to `eval/reports/before_fixes/`; the e2e reports were rerun in place, with copies of the replaced 07:06 versions in `before_fixes/` | The final numbers come from one code state. This departs from "earlier reports stay as they were" for the e2e reports only; the 05:52 versions (32.4 s and 31.3 s) are in git at commit 291b0eb |
| Oct 27 | The guard tags every word of a name Glimmer's second pass reports (and each 3+ letter piece of a hyphenated word) on its own too, and a one-word name the pass reported alone takes in up to two capitalized words on each side, one step only. Every one of these values is stored in the tag map as a known value | On the unseen test in commit 8afe137, syn-0765 leaked after approval: the pass returned "Bennick Cinderfall", the old guard tagged only that exact string, and a later "Bennick" stayed in the text where the final check could not see it. With fixed name-pass answers on 1384 items (`eval/reports/name_parts.md`, no model call), the full-name-only answer leaked 15 items before and 0 after, the last-word-only answer 31 and 1. The cost: more tags and more known values. The sweep finds 30 to 33 extra name tags on 15 to 16 items, against 0 before, mostly family names the hand labels left out. A part gets its own `[Person N]`, not linked to the full name's, so Muse can read one person as two (linking them needs an alias table in the tag map). A part that is also a common word is tagged where the text capitalizes it and the context rules do not see it used as the word ("Grace period ends Friday" after the pass reported "Grace Thornquist"), and a capitalized word next to a one-word name can be taken in when it is not on the stop lists (common words, titles, roster names, words the text writes in lowercase, `guard._NOT_NAMES`). Every stored value is matched in later texts with no model call. The extension does not cross a comma or a line break, and a multi-word name the pass reported takes in nothing |
| Oct 27 | The round after the guard fix reran every final report in place; the last round's versions are in git at commit 8afe137, not copied to a folder | The final numbers come from one code state, and git already keeps the old versions. `eval/reports/final.md` lists the last round under History |
